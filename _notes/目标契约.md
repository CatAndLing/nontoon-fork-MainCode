## 0. 一句话目标

> **【v3 · 现行】轻量化的真实光影。**
> 以**真实光照**为核心（自带光 / 世界光驱动明暗，而不是把光照烘死），阴影按**能力阶梯**（§1.5）
> 逐级加强，**默认零开销**。差异化对象是 **lilToon 那条"全功能 + 真实光影"的重路线**
> —— 用户判断其性能影响过大。

> ~~【v2，已作废】在 VRChat 头像上做出「リアル影システム (for Avatar) PCSS For VRC」那样的真实光影，但开销可接受。~~
> **作废理由**：v2 把"真实"的重心放在**阴影**（PCSS 软影）上，并把"追赶 lilToon"当路径；
> v3 把"真实"限定在**光照**，阴影改为**可选的阶梯**，"追赶 lilToon"整体出局。

**实现手段（用户原话拆解）**：

1. **NonToon 这类着色器**负责**接受世界光线**在模型上构建阴影 —— 便宜，但**依赖世界有可用的实时光照**。
2. **而 VRChat 里"有实时光照计算"的地图优化往往不好、或者只占少数** —— 所以世界光这条路**不可靠**。
3. ⇒ **在模型上挂一盏光源，替代世界光源**，在世界光**不支持或不好**的时候顶上。
4. ~~**但 NonToon 太早、太不完善** ⇒ **要把它完善到接近 lilToon 的水准**（"至少追赶一些"）。~~
   **【v3 作废】** 改为：**把 NonToon 自己的路线做强**（真实光照 + 阴影阶梯，见 §1.5），
   **不是**去接近 lilToon。
5. 配套：**lilToon → NonToon 转换器**（lilToon 素材才是主流）、**光照控制器**（NonToon 缺 LLC 等价物与自发光）、
   全部走 **MA 生态**（易用性）。

### ⇒ 关键推论：**PCSS 与"灯架"是同一条链，不是两件事**

```
自带光源 → Unity 为该光源渲染阴影贴图 → 着色器采样该贴图
         （现在 = 1 次硬件比较采样 = 硬阴影）
         （PCSS  = 多次比较采样 / 距离相关半影 = 软阴影）
```

**我们的 ⑥ 现在就是这条链的前半段。** 所以：
**删掉灯架 = 删掉目标。** 审计那条建议**不予采纳**（前提错误，已作废）。
**PCSS = 在这条链上把采样从 1 次加到 N 次。** 不需要自渲深度图（那条 P-B 才是否决项）。

> ⚠️ **【v3 更正 · 2026-09-18】上面这段的"着色器采样 Unity 阴影贴图"与实测不符。**
> 实测（见 **§2.4**）：着色器里**检索不到**任何"采样私有光 Unity 阴影贴图"的路径；
> `_SelfLightRt*`（⑥ 的着色器侧挂钩）在 0.3.11 已被删（34 → 0）。
> ⇒ **"不需要自渲"这句是 v2 的立场声明，不是已验证的实现事实。**
> 深度来源**尚未定**（a 走 Unity 阴影贴图 / b 恢复自渲，见 §2.4）——
> 在定下来之前，**不得**把这条链当作"已按 a 实现"来声称。
> （这条更正本身也是 `AGENTS.md §5.1`"读到再断言"的一个实例：v2 的推论被自己的实测推翻。）

## 1. 四个支柱（按依赖顺序）

### 支柱 1：~~**把 NonToon 完善到接近 lilToon**~~ → **【v3 改写】把 NonToon 自己的路线做强**
**【v3 作废原写法】**"接近 lilToon"＝**做第二个 lilToon**，与 §0 的目标冲突。

**含义（v3）**：不以"补齐 lilToon 能力清单"为目标；力气放在
① **真实光照**（自带光 / 世界光）② **阴影能力阶梯**（§1.5）③ **迁移便利**（支柱 2）。

**验收（v3）**：真实素材扫描表**仍然要做，但用途反了** —— 它不再是"我们欠什么"的追赶清单，
而是**迁移风险清单**：每一条要么"转过来不塌"，要么转换时**明确报"不支持"而非静默降级**
（措辞要求与 v2 相同）。

现状：
* ✅ 已有/fork 已补：`Shade`(ramp) / `Emission`(**fork**) / `Lighten`+`_LightBoost`(LLC 语义) /
  `MatCaps` / `RimLight` / `RimShade` / `HairSpecular` / `Specular` / `Details` / `DistanceFade` /
  `Nearer` / `ShadowColor`(**fork**，**降级为"转换保真专用"** —— 见 §1.5 T2 的取舍) / `SelfLight`(**fork**)
* ⚠️ **已知缺失不再是"欠债"，而是"迁移会塌在哪"**（转换器**必须**如实报警）：
  `_UseGlitter`、`_UseEmission2nd`、`_UseParallax`、描边贴图族（22/49）、环境反射（24/49）、
  `_BackfaceForceShadow`（6/49）、Fur、Refraction、Gem
* ❗ **不再按频次"排队补"**：频次只用来**排风险的严重度**（高频缺失＝更多素材会塌），
  不构成"必须实现"的义务。

### 支柱 2：lilToon → NonToon 转换器（**必须**）
**验收**：① 逐像素误差在**声明口径**内；② 不达标**当场列为不支持**，不许静默降级；
③ **源码材质零改动**；④ 当前 15/17 警告按"支持 / 近似 / 不支持 / 真失败"**逐条定性**。

现状：机制在，**保真度未验收**。三个未定位症状：(a) 夹克噪点+针织、(b) 头发灰紫、
**(c) 透明容器内含物体**（用户实报；两趟透明变体已存在，但**转换器尚未接线**，
见 `_notes/对照与转换器状态-20260918.md:133`）。

### 支柱 3：光照控制器 + 自发光（LLC 等价物）
**着色器侧不需要实时 `Light`** —— `_LightMinLimit`/`_LightMaxLimit`（含 `[NT-FEAT 27]` 亮度归一化）
+ `Lighten._LightBoost` + `Emission` 模块**就是 LLC 的核心**。
**验收**：VRChat 里能用菜单把亮度上/下限与自发光调到目标值。
现状：着色器侧 ✅、MA 菜单 ✅（**现 17 bit**，见硬约束 5）。**缺"验收"，不缺"再造一个"。**

### 支柱 4：MA 生态接入（易用性）
**验收**：全部功能**声明式**安装；**绝不直接写用户的 FX 控制器 / ExpressionParameters / ExpressionsMenu**；
卸载 = 删一个容器。现状 ✅（`_NonToonLight` 单容器，clip 基路径经 MA API 验证为空）。

### 1.5 【v3 新增】**能力阶梯**（架构原则，长期有效）

> 用户原话：*"让用户按需求选择的阶梯，性能占用从低到高，实现难度从易到难，符合发展规律。"*

| 级 | 内容 | 性能占用 | 实现难度 | 验收口径（**必须能失败**） |
|---|---|---|---|---|
| **T0** 默认 | 上游原生 ramp（现状） | **零**新增采样 | — | 已有（装置 A 逐像素） |
| **T1** | 原生阴影的外围增强：**环境光探测联动** + **锐化** + 距离/遮罩 | **零～极低**（只用已有数据/参数，不加采样） | 易 | 分界过渡带宽度（像素）可测；阴影侧色温/色相随环境变化的数值断言 |
| **T2** | **`fwidth` 解析分界 + 抗锯齿** | 低（几次 ALU，**无采样**） | 中 | 放大下分界**锯齿像素数**下降；与 `_ShadowBorderColor`（44/49 材质）共存不回归 |
| **T3** | **PCSS 实时半影** | 高（**低 20 / 中 36 / 高 60 / 极高 96** 采样/像素，已有档位） | 难 | 半影随遮挡距离单调变化 + **灯只照自己** + 性能等级如实披露 |

**"用户可选"落在哪一层（已定 · 用户选 A）**：**材质属性 + 模块 keyword**。

- T0/T1 走**材质属性**（零成本、不改编译产物）
- T2/T3 走**模块 keyword**（不开就不编译进去 ⇒ 真"零开销默认"）
- ⇒ **不占同步 bit**，因此**不需要解冻** §4 的菜单条款

**为什么把阶梯当架构原则**：它让每一级都自带**可测的成本**与**可失败的收益**，
治本项目历史上"加了东西却说不清代价"的病（见 `AGENTS.md §3` 假绿表）。

> ⚠️ **别和 §5 混淆**：§5 的 **A–F 是步骤编号**；这里的 **T0–T3 是能力层级**。

## 2. ⑥ 的三个**真正未解问题**（目标能不能达成，全看这三条）

> 之前把 ⑥ 当成"已经做完"，是在回避下面三件事。它们是**方案成败点**，不是优化项。

### 2.1 ⚠️ **灯必须只照到自己** —— 当前实现**不满足**
实测（编辑期）：
```
NonToon_RealtimeShadow/Spot Light   Spot, range 8, angle 50, renderMode ForcePixel
cullingMask = 0x00040401 = layer 0 (Default) + 10 (PlayerLocal) + 18 (MirrorReflection)
```
`Default(0)` 是**包含**的 ⇒ 半径 8 米的聚光会**照亮世界里的默认层物件**。
**"不照亮世界"这条当前不成立。**

**要验证的关键假设**：VRChat 运行期把**本机 avatar 放在 `PlayerLocal(10)`**、远端玩家放在 `Player(9)`。
若成立，则掩码可以收成 **`PlayerLocal | MirrorReflection`（去掉 `Default`）** ⇒ **只照到自己（含镜中）**。
**这条必须实测（只能进游戏验证，编辑器里 avatar 在 Default 上，测不出来）。**
⇒ 若假设不成立，则"只照自己"在当前 VRChat 层体系下**可能做不到**，需要另找方案（例如改用
`PlayerLocal` + 关掉 `Default` 的代价评估）。

### 2.2 ⚠️ **双重照亮**：世界光 + 自带光会叠加
世界光好时再叠一盏 0.8 强度的聚光 ⇒ **整体过亮**。
用户的原意是「**在世界光线不支持或者不好的时候**进行」⇒ 这**必须是用户可控的**，
而且 `pcssOn=false` 要真的把灯关掉（现有设计：`SuspendRig()` 推全局 `_NTRTShadowEnabled=0` 并关灯 ✓）。
**待定**：是否需要"只取自带光源的阴影、不取它的亮度"这种半叠加模式。

### 2.3 ⚠️ **性能等级代价必须实测并写进文档**
VRChat 的性能等级**统计 `Light` 组件数量**。一盏灯**不可能"零开销"**。
**验收口径改为**：实测这台 avatar 的等级变化，并写成
「**不是零开销，而是比 リアル影システム 便宜得多**」—— **不许再声称"不影响性能等级"**。
