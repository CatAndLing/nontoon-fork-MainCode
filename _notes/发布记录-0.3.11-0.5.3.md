**教训（并入 AGENTS §3 那张假绿表）**：
> **"没有证据"和"通过"必须分开记。** 判据缺失（探针没跑出来 / 测量无效）与判据为红，
> 是两种不同的状态；把前者读成后者会白修，把前者读成"已通过"会假绿。

## 4. 测试床的三个坑（踩出来的，别再踩）

1. **必须含 VRChat SDK。** 工具包的**必需**依赖 Modular Avatar（→ NDMF）的 asmdef 用
   `overrideReferences: true` 显式引用 `VRCSDKBase.dll` / `VRCSDK3A.dll` / `VRC.Dynamics.dll` /
   `System.Collections.Immutable.dll`。缺 SDK 时它们**本来就编译不过**（实测 540 个错误），
   Unity 以「Scripts have compiler errors」中止 ⇒ 探针根本不会被执行。
2. **必须是标准模板清单，不能是裁剪过的"极简空工程"。**
   - 清单写成 `{"dependencies": {}}` ⇒ `com.vrchat.base` 的 DOTween 报
     `CS1069 Rigidbody2D … forwarded to UnityEngine.Physics2DModule`（还有 AndroidJNI 同类）；
   - 只有内置模块、没有模板自带的 registry 包 ⇒ 缺 `com.unity.test-framework`
     （2022.3 模板经 `com.unity.feature.development` 带入）⇒ VRCSDK 自己的
     `AssetBundleFooterTest.cs` / `VTPTests.cs` 编译不过。
   ⇒ **门禁测试床 = 2022.3 标准模板清单 + VRChat SDK**。否则测的是测试床自己的残缺。
3. **Unity 在"包集变化"时先编译、后完成导入。** 只要包集变了，首次 open 会以
   「Scripts have compiler errors」中止，而错误集逐轮收敛（实测 540 → 39 → 61 → 48 → …到 0）。
   这是导入过程的中间态，**不是本包缺陷**。
   ⇒ 驱动器 `_notes/verify-clean-install.sh` 因此跑**两趟**：第 1 趟只导入（**不带** `-executeMethod`，
   不可能产出报告，退出码照实打印但不作判据），第 2 趟才是判据。
   真实的编译错误不会被两趟掩盖 —— 第 2 趟照样红。
